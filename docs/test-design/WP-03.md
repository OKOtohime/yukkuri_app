## 1. 范围说明

- 被测接口：`PolyglotG2P.convert(text, lang)`，以及流水线实际使用的入口（`pipeline.process_segment` / 文字播报都直接调用它，`lang` 来自 `config.lang`）。可观察结果是音标串（日志中的 `[油库里音标]`）和它能否被 AquesTalk 合成。
- 判定以"读法"为准，不以字典里的某个具体映射为准（需求 4.4 节导语）。比较前做音标归一化（见 4.2 节，待决事项 Q1）。
- "可合成"需要真实库判定，所以 FR-G2P-11/13 的一部分和 QR-FUNC-07 放在 L2（标记 `l2` + `requires_aquestalk`）。L1 中用**由 R1 实测得到的可接受符号表**（第 3.3 节）做快速预判，让 L1 也能在无库环境中发现问题。
- 评价版限制（na/ma 行替换为 nu）不影响返回码，不影响本 WP 的判定。
- 不在本 WP：合成本身（WP-04）；ASR 输出文本的形态（WP-07）。但 ASR 实际会产出的文本形态（ITN 阿拉伯数字、全角符号、日文汉字假名混排）是本 WP 输入空间的主要来源。

## 2. 输入空间分类树

```
G2P 输入
├── lang ∈ {zh, en, ja, 其他值}
├── 字符类别
│   ├── 汉字：基本区 4E00–9FA5 │ 9FA6–9FFF │ 扩展 A/B │ 〇 々 等符号性汉字
│   ├── 假名：平假名 │ 片假名 │ 长音 ー │ 小写假名 │ 罕用（ゔ ゐ ゑ ゝ ヶ ・ ヷ…）
│   ├── 拉丁：ASCII 字母 │ 全角字母 │ 带变音符（é ï）
│   ├── 数字：ASCII │ 全角 │ 汉字数字 │ 带小数点/百分号/负号/千分位
│   ├── 标点：已映射（，。！？、?.,!/） │ 未映射（；：…—“”（）~ 等）
│   └── 其他：空白、换行、emoji、希腊/西里尔/韩文、控制字符
├── 英文词形：高频词 │ 缩写（≤3 无元音 / 含元音 / >3 字母 / 全大写） │ 词表外 │ 缩约（don't、I'm） │ 大小写混合（iPhone）
├── 日文词形：纯汉字词 │ 汉字 + 送假名 │ 汉字 + 助词 は/へ │ 名词 葉/歯/屁 │ 纯假名
├── 混排方式：语种间无空格 │ 有空格 │ 标点相邻 │ 数字与量词相连
└── 长度：空 │ 1 字 │ 常规句 │ 超长（接近 AquesTalk 长度上限）
```

### 3.3 AquesTalk 可接受符号表（L1 预判用的测试数据）

R1 上用 f1 声线对 U+3040–U+30FF 的每个码位做了单独合成和接在「か」后合成，结果作为 L1 的预判表（`qa/data/aquestalk_alphabet.json`，由 `qa/eval/g2p/probe_alphabet.py` 生成，可在 W1 复核）：

- 被拒绝（105）：小写假名单独出现（ぁぃぅぇぉゃゅょゎ、ァィゥェォャュョヮ、ゕゖヵヶ）、ぢ づ ヂ ヅ、ゐ ゑ ヰ ヱ、ゔ ヴ ヷ ヸ ヹ ヺ、・、ゝ ゞ ヽ ヾ、゛゜ 等组合符号、未分配码位；
- ー：单独或开头为 102，接在假名后可接受；
- 停顿符 、。？? 和分隔符 /、重音符 ' 可接受；连续停顿可接受；
- 小写假名只有在构成合法拗音/外来音时可接受（ふぁ、でぃ、きゃ 可以；ゔぁ 不可以）。L1 用"实测合法音节表"判定，不在表里的组合交 L2 复核。

### 4.2 比较口径（待决事项 Q1）

- 比较前对期望和实际都做相同归一化：去掉 `/`（README 中 CPU 写作 `しーぴーゆー`，需求中写作 `しー/ぴー/ゆー`，`/` 只是分隔符）；片假名转平假名（AquesTalk 两者同音）；
- 保留停顿符 、。？ 的位置（停顿属于 FR-G2P-11 的可观察行为），但 `?` 与 `？` 视为相同；
- 标注由测试方起草，**测试负责人评审后定稿**（需求要求"人工标注"）；起草时只依据通行读法，不参考被测代码的输出。

## 5. QR-FUNC-07 模糊测试设计

| 子集 | 条数 | 生成方式 |
| --- | --- | --- |
| A 真实转写文本 | 1,500 | AISHELL-1 / LibriSpeech / CV-ja 抽样清单中的参考文本（已入库的 manifest），模拟 ASR 输出形态 |
| B 结构化随机 | 6,000 | 固定种子：从分类树各叶子（汉字、假名、英文词、数字、标点、符号）按权重拼接 1~40 个片段，lang 均匀取 zh/en/ja |
| C 字符级模糊 | 2,500 | 固定种子：在 BMP 内按 Unicode 区块加权随机取字符（偏重 CJK、假名、标点、全角），长度 1~60 |
| **合计** | **10,000** | |

- 执行：G2P 在主进程；合成放在子进程批量执行（每批 500 条），子进程意外退出即记为"崩溃"并二分定位到具体输入。
- 记录每条的返回码；判定只看 105/107；102（空/格式）与 204（超长，未在库的错误表中）单独统计并报告，不计入 0.1% 的比例（待决事项 Q7）。
- 产物：`qa/reports/wp03/qr_func_07_summary.json`（按子集、按返回码），失败样例全部列出。
