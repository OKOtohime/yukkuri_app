## 1. 范围说明

- 本 WP 以 L1 为主，在组件边界上验证可观察结果（选到的设备参数、送去识别的样本、播放顺序、增益后的 WAV、切出的语音段时长、解析出的路径和密钥）。
- 三处 FR 的"可观察结果"只有接入真实模型才能判定，放在 `qa/integration/`，标记 `l2` + `requires_models`：
  - FR-AUD-03 的"识别结果可用"：48k/44.1k 设备经采集回调后的识别准确率与 16k 直通对比；
  - FR-VAD-03/04 的截断：真实 Silero VAD 上的切段时长；
  - FR-VAD-06：短促非语音声响经 VAD → 最短时长过滤 → SenseVoice 后是否产生文本。
- 不在本 WP：FR-TTS-05 的密钥优先级（WP-04），但 `run.sh` 加载 `.env` 的行为属于 FR-CFG-04，在本 WP 测，发现的优先级问题同时关联 FR-TTS-05。
- 不在本 WP：FR-OUT-08、FR-VMIC、FR-OUT-05/06。IMPL-16、IMPL-18 只作为线索，本 WP 不单独出用例。

## 5. 约定

- 发现缺陷的用例保持原判定，用 `xfail(strict=True, raises=AssertionError)` 标注缺陷编号：缺陷存在时为 xfail，修复后变成 XPASS 并使套件失败，提醒更新。
- 缺陷编号按 WP 分段，避免并行会话冲突：WP-02 使用 DEF-201 起，观察项使用 OBS-201 起。
- 资源缺失时 skip 而不是 ERROR：模型和语料由 `conftest.py` 的标记探测，单个语料文件由 `wp02_util.require_audio()` 检查。
