# DEF-202 运行中调大或关闭"最长单句截断"不生效（界面显示已改，实际仍按启动时的上限截断）

| 字段 | 值 |
| --- | --- |
| 严重程度 | S2（建议：M 级需求不满足；绕过办法是停止后重新启动转换器） |
| 关联需求 | FR-VAD-03、FR-VAD-04、FR-GUI-03 |
| 环境 | R1（[env-R1](../env-R1.md)），sherpa-onnx 1.13.8。W1 上该用例受 DEF-211 阻塞 |
| 版本 | b993c40 |
| 发现于 | WP-02，用例 `test_fr_vad_03_runtime_change_takes_effect[6.0->12.0 / 2.0->15.0 / 6.0->0.0]` |
| 可复现性 | 必现 |

## 前置条件

VAD 模型就绪；一段 16.5s 几乎无停顿的连续朗读（LibriSpeech `1221-135767-0011`）。

## 复现步骤

GUI 中：启动转换器（截断 6.0s），运行中把"最长单句截断"滑块拖到 12s，或关闭截断开关，然后连续说话 15s 以上。

L1/L2 等价操作：`SileroVAD(..., max_speech_duration=6.0)` 构造后调用 `set_max_speech_duration(12.0)` 或 `set_max_speech_duration(0.0)`（GUI 的 `_on_max_speech_changed` / `_on_max_speech_switch_toggled` 正是调用这个方法），再按 800 样本块送入音频。

## 期望结果

- FR-GUI-03：截断设置"在运行中修改后实时生效"。
- FR-VAD-04：关闭后长句不被切断。
- 判定口径：运行中改为 X 后的切段结果，应与"启动时就设为 X"一致（最长段相差 ≤ 0.2s）。

## 实际结果

| 启动时上限 | 运行中改为 | 实际切段（秒） | 启动时即为新值的切段（秒） |
| --- | --- | --- | --- |
| 6.0 | 12.0 | 9.30、6.52 | 12.02、4.03 |
| 2.0 | 15.0 | 5.11、3.95、6.52 | 15.06、0.99 |
| 6.0 | 关闭 | 9.30、6.52 | 16.05（不切） |
| 6.0 | 3.0 | 正确 | — |
| 15.0 | 2.0 | 正确 | — |

调小有效，调大和关闭无效。

## 初步分析

`yukkuri/audio/vad.py:77-91` `set_max_speech_duration()` 通过 `self._detector.config.silero_vad.max_speech_duration = ...` 修改配置。读回该属性能看到新值，但检测器在构造时已经复制了配置，内部仍按构造时的上限强制结束语音段。调小之所以有效，是因为包装层自己在 `accept_waveform()`（`:102-108`）里按新上限调用 `flush()`；调大或关闭时包装层不再干预，但底层的旧上限仍在起作用。
