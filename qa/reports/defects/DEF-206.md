# DEF-206 经 `run.sh` 启动时，`.env` 覆盖已设置的系统环境变量

| 字段 | 值 |
| --- | --- |
| 严重程度 | S3 |
| 关联需求 | FR-CFG-04、FR-TTS-05 |
| 环境 | R1 |
| 版本 | b993c40 |
| 发现于 | WP-02，用例 `test_fr_cfg_04_run_sh_env_precedence` |
| 可复现性 | 必现 |

## 复现步骤

1. 项目根目录 `.env`：`AQUESTALK_DEV_KEY=from_env_file`。
2. `AQUESTALK_DEV_KEY=from_os_env ./run.sh`。

## 期望结果

FR-TTS-05：密钥来源优先级为 CLI 参数 > 系统环境变量 > `.env`。直接运行 `yukkuri`/`python -m yukkuri.cli` 时就是这样（`.env` 不覆盖已有变量，用例 `test_fr_cfg_02_env_does_not_override_os_env` 通过）。

## 实际结果

经 `run.sh` 启动的进程看到的是 `from_env_file`。同一台机器上，用 `run.sh` 和用 `yukkuri` 启动会得到不同的密钥。

## 初步分析

`run.sh:7-11` 用 `set -a; . "$SCRIPT_DIR/.env"; set +a` 加载，shell 赋值会无条件覆盖已有的同名环境变量。

另：README"密钥配置方式"一节写"按优先级由高到低"依次为 `.env`、环境变量、CLI 参数，与 FR-TTS-05 基线相反（文档问题，交 WP-04 一并处理）。
