# DEF-201 `setup_models.py --vosk zh` 安装的中文模型，程序和 `--check` 都找不到

| 字段 | 值 |
| --- | --- |
| 严重程度 | S2（建议：M 级需求不满足；Windows 上没有 `setup_models.sh` 可用，官方工具内无绕过办法） |
| 关联需求 | FR-CFG-03、FR-ASR-05、FR-MDL-02、FR-MDL-07 |
| 环境 | R1、W1（L1 用例在两个平台上都复现）；WP-01 在 R1 的真实下载中首先观察到（P-01） |
| 版本 | b993c40 |
| 发现于 | WP-02，用例 `test_fr_cfg_03_installer_layout_is_loadable[vosk_zh]` |
| 可复现性 | 必现 |

## 前置条件

数据目录中没有 `model_cn/`、`model/`。

## 复现步骤

1. `python setup_models.py --vosk zh`（或 GUI 模型管理中下载 Vosk 中文）。
2. `python setup_models.py --check`。
3. `python -m yukkuri.cli --engine vosk --lang zh`。

## 期望结果

FR-CFG-03："用项目自带的工具下载或导入的资源，程序启动时都能找到"。

## 实际结果

- 模型被装到 `<数据目录>/model_zh/`。
- `--check` 显示"Vosk 中文模型 (zh): [未安装]"；`--vosk zh` 再次执行时又会重新下载。
- CLI 报"未找到 Vosk 模型目录 (语种: zh)"，退出码 1。
- 用 `setup_models.sh --vosk zh`（Linux）则装到 `model_cn/`，能找到。两个官方工具结果不一致。

## 初步分析

- 安装侧：`yukkuri/model_downloader.py` `download_vosk()` 用 `model_{lang}` 作为目标目录，`lang="zh"` 时为 `model_zh`。
- 加载侧：`yukkuri/config.py` `find_vosk_model_dir()` 对 zh 只查 `model_cn`、`model`；`check_model_status()` 的 `vosk_zh` 也只查这两个目录。
