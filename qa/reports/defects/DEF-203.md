# DEF-203 重采样对短于 41 个样本的输入抛异常或返回错误长度，可使采集回调中止

| 字段 | 值 |
| --- | --- |
| 严重程度 | S3（建议：常规开流路径块长固定为 50ms，不触发；只在回退路径或其他调用方传入短数据时触发） |
| 关联需求 | FR-AUD-03 |
| 环境 | R1、W1（L1 用例两个平台都复现）。默认安装没有 scipy，走纯 NumPy 分支 |
| 版本 | b993c40 |
| 发现于 | WP-02，用例 `test_fr_aud_03_resample_any_length`、`test_fr_aud_03_callback_any_block_size`（hypothesis） |
| 可复现性 | 必现 |

## 复现步骤

```python
import numpy as np
from yukkuri.audio.resample import resample_audio
resample_audio(np.zeros(30, np.float32), 48000, 16000)   # ValueError: fp and xp are not of the same length.
resample_audio(np.zeros(1, np.float32), 8000, 16000)     # 返回 41 个样本，应为 2 个
```

采集层：`MicrophoneStream._audio_callback` 在设备采样率 ≠ 16k 时，收到 2~40 帧的数据块即抛 `ValueError`。

## 期望结果

FR-AUD-03：非 16k 设备"也能正常采集"。重采样对任意长度输入都应返回长度约为 n·目标率/原率 的结果，不抛异常。

## 实际结果

- 降采样（48k/44.1k/32k/22.05k/96k → 16k），输入长度 2~40：`ValueError`。
- 升采样（8k → 16k/44.1k/48k），输入长度很短时：返回 41 个样本（长度错误）。
- 在 PortAudio 回调中抛异常会使输入流中止，之后不再有音频送去识别。

## 初步分析

`yukkuri/audio/resample.py` `_convolve_with_padding()`：输入不长于滤波器（41 抽头）时走 `np.convolve(audio, fir, mode='same')`，`'same'` 模式的输出长度是两者中较大的那个（41），之后与 `np.arange(axis_len)` 做插值时长度不匹配。

触发条件：`MicrophoneStream.start()` 常规路径按 50ms 固定块长开流，不会出现短块；指定块长失败后的回退路径（`capture.py:146-155`）不指定块长，块长由 PortAudio/主机 API 决定，可能出现很小的块（例如 PipeWire 低延迟量子 32 帧）。
