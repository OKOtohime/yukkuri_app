# DEF-211 Windows 上 VAD 切出的语音段全部为空，SenseVoice 模式不产生任何识别和合成

| 字段 | 值 |
| --- | --- |
| 严重程度 | S2（建议；README 声明 Windows 为实验性，按 6.2 节可下调一级，由测试负责人裁定） |
| 关联需求 | FR-VAD-01、FR-OUT-01、QR-PORT-01；阻塞 W1 上 FR-VAD-03/04 的验证 |
| 环境 | W1（[env-W1](../env-W1.md)），sherpa-onnx 1.13.8；R1 不复现 |
| 版本 | b993c40 |
| 发现于 | WP-02，用例 `test_fr_vad_01_segments_carry_audio`、`test_fr_vad_01_pipeline_reaches_asr` |
| 可复现性 | 必现（W1 上 3 种截断配置、2 个用例均复现） |

## 前置条件

W1，`YUKKURI_DATA_DIR` 下有 `silero_vad.onnx`。

## 复现步骤

1. 用 `SileroVAD(vad_path, min_silence_duration=0.3, max_speech_duration=6.0)` 按 800 样本块送入一段 16.5s 的连续朗读（LibriSpeech `1221-135767-0011`）。
2. 查看 `accept_waveform()` / `flush()` 返回的各段长度。
3. 按 `YukkuriPipeline.run()` 主循环的做法把各段交给 `process_segment()`，用桩 ASR 记录调用。

## 期望结果

FR-VAD-01："说话后停顿达到设定时长即断句，这句话被识别并合成"。切出的段应包含该段语音（R1 上为 6.01s、6.02s、4.03s）。

## 实际结果

- 段数与 R1 一致（3 段），但每段都是 0 个样本：`3 段中有空段：[0, 0, 0]`。
- `process_segment` 按"短于 0.3s 丢弃"把它们全部丢掉：`ASR 只被调用 0 次`。
- 也就是说 W1 上 CLI 默认的 SenseVoice 模式、以及 GUI 中启用 VAD 的所有模式，说话后都没有任何输出（文字播报不经过 VAD，不受影响）。

## 初步分析

`yukkuri/audio/vad.py:112-114`（`accept_waveform`）和 `:122-124`（`flush`）先 `self._detector.pop()`，再读 `seg.samples`：

```python
seg = self._detector.front
self._detector.pop()
segments.append(np.array(seg.samples, dtype=np.float32))
```

`front` 返回的是检测器内部队列首元素的引用，`pop()` 之后它已经失效。直接用 sherpa-onnx 原生接口对照（同一音频、同一配置）：

| 读取时机 | R1 | W1 |
| --- | --- | --- |
| `pop()` 之前读 `samples` | 9.3s | 9.3s |
| `pop()` 之后读 `samples`（产品写法） | 9.3s | **0.0s** |

Linux 上读到的是已释放但尚未被覆盖的内存，属于偶然正确；Windows 的分配器行为不同，读到空数组。先读 `samples` 再 `pop()` 即可避免。

WP-01 在 W1 上的 VAD 冒烟测试只检查了段数（"切出 1 段"），没有检查段内样本，所以当时没有发现。
