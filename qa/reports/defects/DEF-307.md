# DEF-307 映射表缺少 dia、tei 等 12 个普通话音节，词组语境下音节被静默丢弃（发嗲 → ふぁー）

| 字段 | 值 |
| --- | --- |
| 严重程度 | S4（建议：M 级需求 FR-G2P-03 不满足，但实际触发极少：pypinyin 4.7 万词组中仅「发嗲」一例） |
| 关联需求 | FR-G2P-03 |
| 环境 | R1、W1 |
| 版本 | b993c40 |
| 发现于 | WP-03，用例 `test_fr_g2p_03_all_dictionary_syllables`、`test_fr_g2p_03_phrase_context_syllables` |
| 可复现性 | 必现 |

## 复现步骤

```python
from yukkuri.g2p import text_to_yukkuri_polyglot as g
g("发嗲")   # 'ふぁー'，嗲（dia）没有读音
```

## 期望结果

FR-G2P-03："普通话所有合法音节都能读出，不会有音节被静默丢弃"（README："拼音 100% 覆盖"）。

## 实际结果

- pypinyin 0.55.0 字典中 U+4E00–U+9FA5 范围内出现的音节，有以下不在 `PINYIN_MAP` 中：dia（嗲）、tei（忒）、ng/hng（嗯、哼）、len（啉）、nia（㖸 等）、ê（欸），以及只出现在扩展区的 cei、din、wong、bong、biang；
- 单字默认读音不会产生这些音节（QR-FUNC-06 的 3500 字全部命中），但 pypinyin 按词组选读音时会：「发嗲」→ fa dia，dia 查表失败后以拉丁字母形式进入音标，再被清洗规则删除，没有任何提示。

## 初步分析

`yukkuri/g2p/polyglot.py:122` 的 `PINYIN_MAP.get(py, py)` 在缺键时回退为拼音原文，随后 `normalizer.clean_koe_string` 删除所有拉丁字母。补全映射表中缺失的音节即可。
