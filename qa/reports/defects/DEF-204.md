# DEF-204 `.env` 以 UTF-8 BOM 开头时第一行的密钥被静默忽略

| 字段 | 值 |
| --- | --- |
| 严重程度 | S3（建议：M 级需求，但有绕过办法——另存为无 BOM 的 UTF-8） |
| 关联需求 | FR-CFG-02、FR-TTS-05 |
| 环境 | R1、W1（L1 用例两个平台都复现） |
| 版本 | b993c40 |
| 发现于 | WP-02，用例 `test_fr_cfg_02_env_parsing[utf8_bom]` |
| 可复现性 | 必现 |

## 复现步骤

1. Windows PowerShell 5.1（Windows 10 自带）：`"AQUESTALK_DEV_KEY=xxxx" | Out-File -Encoding utf8 .env`，该命令会写入 BOM。记事本的"UTF-8 with BOM"选项同样如此。
2. 在该目录启动 CLI 或 GUI。

## 期望结果

FR-CFG-02：项目根目录 `.env` 中的密钥对 CLI 和 GUI 都生效。

## 实际结果

`AppConfig().dev_key` 为 `None`，没有任何提示，程序按评价版运行。BOM 后面的行（第二行起）不受影响。

## 初步分析

`yukkuri/config.py:53` 用 `encoding="utf-8"` 打开文件，BOM 被保留为第一行开头的 `﻿`，第一个键名变成 `"﻿AQUESTALK_DEV_KEY"`。改用 `utf-8-sig` 即可。
