## 4. 预备发现（待相应 WP 正式确认并出报告）

| ID | 现象 | 可能关联 | 交给 |
| --- | --- | --- | --- |
| P-01 | `setup_models.py --vosk zh` 把模型安装到 `model_zh/`，但程序查找（`find_vosk_model_dir`）和 `--check` 只认 `model_cn/` 或 `model/`。结果是 `--check` 显示 Vosk zh "未安装"，CLI 的 `--engine vosk --lang zh` 也找不到模型 | FR-CFG-03、FR-MDL-02、FR-ASR-05 | WP-04 |
| P-02 | `test_s6_get_default_data_dir` 只在 Windows 上失败 | QR-MNT-01、FR-CFG-01 | WP-02 |
| P-03 | 声线库就绪后，`test_library_resolution` 只在 Windows 上失败 | FR-CFG-03、QR-MNT-01 | WP-02、WP-04 |
| P-05 | Windows 上自动选择输出设备时，取第一个名称含 "cable input" 的 WASAPI 设备。装了 Hi-Fi Cable 后，它命中的是 `Hi-Fi Cable Input (2- …)`（索引 26，排在真正的 `CABLE Input` 27 之前），合成音会送到错误的线路。装了 VB-CABLE A+B（`CABLE-A Input`）的用户同样会受影响 | FR-OUT-05、FR-VMIC-05、QR-COMP-02 | WP-11 |
| P-04 | 官方包中同时有 32 位（`lib/`、`lib32/`）和 64 位（`lib64/`）库，导入时都写到 `lib64/<voice>/` 下的同一路径，最终保留哪个取决于压缩包内条目的顺序（这次两个平台都恰好是 64 位版本留下）。Windows 包里 `samples/.../Release/AquesTalk.dll` 还被装到了 `lib64/Release/` 下 | FR-MDL-05 | WP-04 |

为避免掩盖 P-01，测试环境中**没有**手动创建 `model_cn` 来绕过。WP-07 评测 Vosk zh 时，由评测脚本直接指定模型目录。
